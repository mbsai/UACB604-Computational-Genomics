FASTA

FASTA: a name and a sequence

>NC_001422.1 Escherichia phage phiX174, complete genome
GAGTTTTATCGCTTCCATGACGCAGAAGTTAACACTTTCGGATATTTCTGATGAGTCGAAAAATTATCTT
GATAAAGCAGGAATTACTACTGCTTGTTTACGAATTAAATCGAAGTGGACTGCTGGCGGAAAATGAGAAA
… 77 lines of 70 bases, then the last 66 …
  • Header line starts with >: the first word is the ID, the rest is a free description
  • Sequence on the following lines (often wrapped at 60–80 characters)
  • Many records in one file = “multi-FASTA”
  • Used for DNA, RNA and protein; no annotation, no quality
Your genome as a string (1.1) in its simplest file form. Nearly every tool accepts FASTA. Common extensions: .fa, .fasta, .fna (nucleotide), .faa (protein).

FASTQ maths

FASTQ: sequence plus quality, four lines per read

@SRR41113426.1 M01380:141:000000000-C9GH3:1:1102:24051:2228/1
GGAGTTTAATCATGTTTCAGGGGTTTATTTCTCGCCATAATTC…
+
GGGFGGGGGGGGGGGAFGGGGGGFDGGGGGGGGGGGDFFGGGG…
  1. @ + read name (instrument, run, flow cell, tile, x, y, mate)
  2. the sequence
  3. + separator
  4. one quality character per base

Quality characters encode Phred scores as ASCII code − 33 (“Phred+33”, standard since ~2011; some old Illumina files used +64).

Why add 33? ASCII codes 0–32 are invisible control characters and the space. Code 33 (!) is the first printable one, so Q0 → !.

Real φX174 MiSeq read above: G = 71 − 33 = Q38.

4 min. Watch out: '@' can also appear as a quality character, so never parse FASTQ by searching for lines that start with '@'. Count lines in fours.

Raw signal and long reads biology

fast5, POD5 and BAM

  • fast5: Nanopore's original format for the raw current (squiggles, Lecture 2.3), built on HDF5, a general container for big numeric data organised like folders.
  • POD5: Nanopore's newer, faster raw-signal format, replacing fast5.
  • BAM: binary, compressed; PacBio delivers HiFi reads as unaligned BAM. You'll meet aligned BAM/SAM in later units.
  • Binary files start with a “magic number”: HDF5 files begin with the bytes \x89HDF.
3 min. Students won't open fast5 by hand; they should know raw signal is kept so it can be re-basecalled with better models later.

How big is a FASTQ file?

FASTQ, uncompressed

Bytes per read ≈ header (~60) + sequence (L) + “+” line (1) + quality (L) + 4 line breaks.

$$\text{reads} = \frac{\text{coverage} \times G}{L}$$

Human, 30×, 150 bp: 620 million reads × ~365 bytes ≈ 226 GB uncompressed.

Compression ratios vary (quality strings compress worse than bases); ÷4 is a rough guide.

4 min. Ask: what fraction of a FASTQ file is quality? About half, so quality binning (e.g. NovaSeq's few quality levels) saves a lot of space.
